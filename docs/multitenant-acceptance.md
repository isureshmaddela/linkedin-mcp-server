# Multi-tenant acceptance matrix

The scope document ends with sixteen release criteria that "pass in staging with real billing in test mode and three pilot organizations". This file says which automated tests cover each one today and what is still open. Nothing here was run in a staging environment, against Stripe, or with pilot customers; the tests run in-process (stand-in billing provider, S3 and OIDC/SAML stubs, a real Chromium against an ATS stub).

Run them: `uv run python -m pytest tests/test_cloud_*.py -q`.

## What this does not prove

- Run against emulators and local stand-ins only: Stripe (stripe-mock validates request shapes; no Stripe account), identity providers (a real Keycloak for OIDC and SAML; not Okta, Entra or Google), KMS (AWS KMS and Vault transit stubs), the remote sign-in broker (a stub login site, not LinkedIn's live sign-in). PostgreSQL 16 was run in Docker (row-level security, the copy command and the hosted-shell suite); poolers, replicas and failover were not. The Docker stack and the Kubernetes manifests (on kind) were run; Terraform was validated, scanned and linted but never planned or applied. See [multitenant.md](multitenant.md#differences-from-the-scope-document-and-known-gaps).
- Real billing in test mode, the three pilot organizations, and an external penetration test are outside what could be done here.
